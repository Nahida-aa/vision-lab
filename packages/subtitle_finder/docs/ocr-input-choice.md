# 喂 OCR：关键帧（原始帧） vs 去背景字幕图（ISA/mask）

> 实验结论：**在这个测试视频上，喂「关键帧原始帧」比喂「去背景 ISA/mask」识别更准**。
> 去背景二值化会丢失文字笔画，导致 OCR 误判/丢字。

## 实验（用 subtitle_ocr 对同一字幕段的三种图 OCR）

| 段（时间） | C++ RGB（原始帧） | C++ ISA（去背景） | Rust 原帧 | Rust mask（去背景） |
|---|---|---|---|---|
| 段0 (133-932) | **弱者** | 空（丢） | **弱者** | 空（丢） |
| 段1 (933-2265) | **这小子也真是敢说** | 这小子也真量敢说（错） | **这小子也真是敢说** | 这小子也真量敢说（错） |
| 段2 (2266-3499) | **这可是剑仙啊** | 这可是剑仙响（错） | **这可是剑仙啊** | 这可是剑仙啊 |
| 段3 (3700-5032) | **不行我得出手了** | 不行我得出手了 | **不行我得出手了** | 不行我得出手了 |

- 真实字幕以 C++ RGB + Rust 原帧（两个独立管线一致）为准：段1="这小子也真是敢说"、段2="这可是剑仙啊"。
- **C++ ISA 与 Rust mask（去背景图）识别反而不准**：段0 丢字、段1"量"（应为"真"）、段2"响"（应为"啊"）。
- **现象是「文字变粗、变模糊」，不是丢笔画**（用户观察）。笔画加粗 → 相邻笔画粘连 →
  OCR 误判（"真"→"量"、"啊"→"响"）。

## 为什么文字变粗/模糊（来源，C++ 和 Rust 一样）

- **变粗**：`FilterTransformedImage` 的 `ImSF = ImSF ∩ dilate(NE)`（膨胀边缘图后与 ISA 交集，
  边缘加宽），以及 `ExtendImFWithDataFromImNF`（用过滤前快照扩展文字行），都会让文字比
  原始帧更粗。**这是 ISA 生成的固有现象，C++ 同样如此**（用户观察确认）。
- **模糊**：C++ ISA 存为 **JPEG（有损压缩）**，引入压缩伪影加剧模糊。Rust mask 存 PNG（无损）
  但仍识别差，说明主因是**二值化/膨胀使文字变粗**（JPEG 只是加剧模糊）。

## 结论

- **不要**把去背景 ISA/mask 直接喂 OCR —— 文字变粗/模糊导致笔画粘连（"真"→"量"、"啊"→"响"），
  识别反而不如原始帧。**C++ 和 Rust 的去背景图都一样变粗模糊**。
- **应该**喂**关键帧原始帧**（配合 subtitle_ocr 的 `--subtitle-only` bottom_only ROI）。
- VideoSubFinder 官方推荐 ISA，是配套传统 OCR（FineReader/Subtitle Edit 等）对黑白粗体文字
  更鲁棒；RapidOCR（深度学习）对变粗的图敏感，故用原始帧更稳。
- 若后续要实现"去背景喂 OCR"，需先**减弱 dilate/extend 对文字本身的加粗**、保证笔画清晰、
  并考虑**无损存储（PNG）**替代 JPEG，否则会退化。

## 建议架构

```
subtitle_finder（关键帧 + 时间轴）
    │
    ├─ 原始关键帧 BGR ──► subtitle_ocr（bottom_only ROI）──► 文本   ← 当前推荐
    │
    └─（未来）增强版去背景 ISA ──► subtitle_ocr ──► 文本   （需先做字符增强）
```

当前 `subtitle_finder` 输出 `Keyframe{ frame: 原始BGR, mask: ISA }` 两者都有，
下游 `subtitle_ocr` 用 `frame`（原始帧）即可。
